Description

Servexa is a full-stack field service management platform that connects customers with technicians. Customers submit service requests, track work orders, and pay invoices through bKash; technicians update assigned work; administrators manage users, assignments, invoices, and audit logs.

Main Technology Stack

Next.jsReactTypeScriptTailwind CSSTanStack QueryReact Hook FormZodExpress.jsNode.jsPostgreSQLPrisma ORMJWTGoogle OAuthbKash

Key Features

  • Customer tools: register with email or Google, manage addresses, submit and cancel requests, pay invoices via bKash.
  • Technician tools: view assigned jobs, update work-order status, manage availability.
  • Admin tools: manage users, technicians, services, assignments, invoices, and notifications.
  • Audit and stats: audit logs and platform statistics for admins.
  • Secure API: JWT with refresh tokens, role and object-level authorization, Zod validation, Helmet, rate limiting.
  • Versioned REST API: consistent JSON responses with pagination under /api/v1, documented in Apidog.

How It Works

  1. 1. Service request
    Customer submits a request.
  2. 2. Work order
    Request is reviewed and a work order is created.
  3. 3. Assignment
    Admin assigns a technician.
  4. 4. Progress
    Technician updates work-order status.
  5. 5. Invoice
    An invoice is created for the work order.
  6. 6. Payment
    bKash payment is verified by the backend and records are updated.

A Next.js (App Router) and TypeScript frontend talks to a modular Express.js and TypeScript API (routes, controllers, services) backed by PostgreSQL through Prisma, using transactions for multi-step operations.

Challenges Faced

  • Multi-role workflow: coordinating requests, work orders, technician assignments, and completion across customer, technician, and admin roles.
  • bKash payments: linking invoices to payment creation, callbacks, verification, and status updates.
  • Access control: enforcing authentication, role permissions, and object-level access so users only reach their own resources.
  • Backend consistency: keeping API responses, validation, pagination, and error handling uniform across a modular backend.

Potential Improvements & Future Plans

  • Automated testing: expand test coverage for the payment and work-order flows.
  • Monitoring: add logging and observability for the API and payment callbacks.
  • Accessibility and performance: continue improving both across dashboards and forms.
